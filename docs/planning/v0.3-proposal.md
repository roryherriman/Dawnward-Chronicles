# v0.3 proposal: Character Foundations and Story Intelligence

Status: **final scope for approval. Not implemented.** The general direction was approved on 2026-10-25, subject to the decisions recorded below. Implementation starts only after:

1. the v0.2 in-game testing and PR review are complete and v0.2 is merged;
2. a new branch `feat/v0.3-character-foundations` is created from the updated `main`;
3. you explicitly approve this final scope.

## Recorded decisions

| # | Decision |
|---|---|
| 1 | **Three starting points, all supported:** import from the selected TRP3 profile (**preferred when a compatible profile exists, never required**); paste or write a biography in Dawnward; start blank and grow organically |
| 2 | **TRP3:** public read APIs wherever they exist. The deprecated `GetInfo("about")` reader may be used **only** inside an isolated, version-checked, read-only adapter for audited **3.4.1**. Anything unsupported fails safely and offers manual entry. TRP3 files, saved data and internal structures are never modified. |
| 3 | **Three distinct layers: Source → Interpretation → Canon.** Interpretations never become canon silently. Every approved fact keeps its provenance. |
| 4 | **Nine fact categories:** origin, relationship, motivation, fear, belief, trait, event, place, other. They stay extensible as data, without extra UI. |
| 5 | **Story prompts (M6), as a small prototype:** 1–3 context-sensitive writing prompts using approved facts only, with a **Write in Journal** action, neutral prompts for blank characters, and no autonomous decisions or personality changes |
| 6 | **Privacy:**<br>• Facts default to private, and stored biographies are private.<br>• Biographies never appear in share exports.<br>• Full biographies go into backups only on explicit opt-in.<br>• Simulation mode stays isolated.<br>• A TRP3 import never overwrites approved canon. |
| 7 | **UI:** the existing Journal, Character and Story sections only. Onboarding is optional and light, with no new tabs, dashboards or configuration screens. |

## Architecture: three layers

```
  SOURCE (verbatim, private)        INTERPRETATION (proposals)             CANON (approved)
  ──────────────────────────        ──────────────────────────             ────────────────
  TRP3 structured snapshot   ──┐    candidate facts      (from fields,  ──►  facts
  TRP3 biography snapshot    ──┼──► (status: open)        sentences,        (category, statement,
  pasted / written biography ──┤    story insights        questions)        provenance, visibility)
  guided-question answers    ──┘    (possible motivation,                        │
  profile · family · history ───►    conflict, opportunity)                      ▼
  journal milestones         ───►         │ player: approve / edit /       story prompts (M6),
                                          │ reject / skip                  later: decisions (v0.4)
                                          └──────────────────────────────►
```

- **Source** stores what the player wrote, exactly as written, plus a normalised copy of imported structured fields. Dawnward never edits a source; capturing again replaces it as a whole.
- **Interpretation** stores everything Dawnward *proposes*:
  - **candidate facts**: "this sentence or field may be a fact";
  - **story insights**: possible motivations, conflicts and story opportunities derived from canon or sources.

  Each has a stable key, a status (`open`, `rejected` or `promoted`) and a pointer to its origin.
- **Canon** holds approved facts only. The only way in is a player action: approving or editing an interpretation, or writing a fact directly.
- **Provenance** on every fact:
  - `origin` (trp3-field, trp3-biography, paste, written, answers, profile, journal or player);
  - `sourceId` and `ref` (field name, or sentence number);
  - an `excerpt` of up to 300 bytes, quoting the source text at approval time, so the fact stays traceable even after its source is captured again;
  - `interpreted`: true when the statement paraphrases rather than quotes;
  - `interpretationKey`, when the fact came from a proposal.

### Data model: schema v3 (additive and idempotent, like v1→v2)

```
character.sources         = { [id] = { kind, capturedAt, ref, text?, fields?, bytes } }   -- private
character.interpretations = { { key, kind = "candidate" | "insight", category, statement,
                                 origin, sourceId?, ref?, status, createdAt } }            -- capped
character.facts           = { { id, category, statement, subject?, provenance, visibility,
                                 createdAt, updatedAt? } }                                  -- canon
```

- **Categories** are a data table (`id`, `label`, `order`) in `Core/Facts.lua`. Adding one later is a data change; the UI groups facts by whatever the table lists. Unknown categories in loaded data are shown under **Other** and keep their original ID.
- **Caps (proposed):** 200 facts, 300 interpretations, 3 sources of up to 16 KB each per character. Text over a cap is refused with an explanation, never cut short silently. Rejected interpretations keep their key, so they aren't suggested again.
- **The existing profile, family and history** stay where they are. They can *produce* candidate facts but are never duplicated automatically.
- **Importing again** never touches canon:
  - the new capture replaces the source;
  - new candidates are added;
  - candidates already promoted or rejected are skipped by key;
  - facts whose source passage changed get a small "source changed" note, and their text stays the same.

### Privacy and isolation
- Facts and interpretations start **private**, and sources are always private.
- **Share exports** contain public facts only: never sources and never interpretations.
- **Backups** contain facts and interpretations. Sources are included only with an explicit option (`/dawnward export backup biography`, plus a checkbox-style toggle in settings that is off by default and resets to off each session).
- **Simulation mode:** all three layers live in the active database, so experiments never touch real canon. Reading TRP3 in simulation mode writes the source into simulation data only.

### Modules

| Module | Layer | Responsibility |
|---|---|---|
| `Core/Sources.lua` | Core | Store and replace verbatim sources; strip TRP3 text tags for *display only*; split text into paragraphs and sentences |
| `Core/Interpretations.lua` | Core | Deterministic candidate and insight generation with stable keys; the review queue; promotion to canon only through `Facts.Approve` |
| `Core/Facts.lua` | Core | Canon: categories, create/edit/delete, provenance, caps, queries |
| `Core/Questions.lua` | Core | 6–8 packaged guided questions for blank characters, which produce candidates |
| `Core/Prompts.lua` | Core | Packaged prompt templates with conditions on canon, plus neutral prompts |
| `Integrations/TRP3/Reader.lua` | Integration | **The only TRP3 reader.** Version-checked, read-only and wrapped so it can't raise errors. Returns copies of strings and numbers only. |

The TRP3 reader is the only file that touches TRP3, and it does nothing unless the player clicks **Read my TRP3 profile**.

### TRP3 reader (read-only)

| Data | Access | Gate |
|---|---|---|
| Name, title, race, class | Public getters (already used in v0.2) | Public API |
| Age, birthplace, residence, eyes, height, misc fields, personality traits | `CurrentUser:GetCharacteristics()`, a **public** method that returns TRP3's live table, deep-copied at once | Public method; field names from the 3.4.1 audit |
| Preset trait names | TRP3 stores only the preset's position (1–11). Dawnward ships its own English names in the 3.4.1 order. | **3.4.1 only.** Other versions show custom traits and skip presets. |
| Biography (About, templates 1–3) | `CurrentUser:GetInfo("about")`, **deprecated** | **3.4.1 only, inside the adapter.** Anything else falls back to "paste your biography". |

**Refusals, each with a clear message and the paste path as fallback:**
- TRP3 not loaded;
- TRP3 version not audited;
- TRP3's default profile is active;
- the active profile isn't the one bound to this character;
- a read fails or returns an unexpected shape.

## Onboarding (optional, inside the Character section)

The Character section gains one **Foundations** area below the profile. With no facts yet it offers three equal choices, **Read my TRP3 profile** being listed first only when a compatible TRP3 profile is detected:

1. **Read my TRP3 profile:** binds the profile to this character after confirming its name, captures it, and shows candidates for review.
2. **Paste or write a biography:** opens an editor or paste box. The text is saved verbatim and shown as a sentence list; clicking a sentence offers **Make this a fact…** with the sentence pre-filled and a category to pick.
3. **Answer a few questions:** short guided questions, any of which can be skipped.

Afterwards the area shows approved facts grouped by category (Edit, Delete, visibility) and one line, **Suggestions to review (N)**, which opens a one-at-a-time review with **Approve**, **Edit then approve**, **Reject** and **Skip**.

The **Story** section shows 1–3 prompts with **Write in Journal**, which opens the existing journal editor pre-filled with the prompt as the title. No new tabs.

## Milestones

| # | Milestone | Done when |
|---|---|---|
| M1 | **Schema v3 and canon:** `Facts`, categories, provenance, caps; migration v2→v3; privacy in exports; simulation isolation | L1: the migration is additive and idempotent; v0.2 data is unchanged; secret, private and source data never appear in share exports |
| M2 | **Interpretation layer and review:** `Interpretations`, the review queue, approve/edit/reject/skip, rejected keys remembered | L1/L2: the only path into canon is a player action; re-running generation never changes canon |
| M3 | **Blank characters:** guided questions, and candidates from the existing profile, family, history and milestones | A character with no biography reaches approved facts using Dawnward alone |
| M4 | **Pasted or written biographies:** verbatim sources, tag stripping for display, the sentence list, "Make this a fact…" | Works without TRP3. The source survives save and reload byte-for-byte. |
| M5 | **TRP3 import:** profile binding, structured-field candidates, preset names, About capture through the 3.4.1 adapter | L2 against an extended 3.4.1 fake: no setters called, no references kept; unknown version, default profile or wrong profile → refusal plus paste path; re-import never changes canon |
| M6 | **Story prompts prototype:** 1–3 prompts from approved facts and recent milestones; neutral prompts with no facts; **Write in Journal** | Deterministic; uses canon only; never shows interpretations or sources |
| M7 | Docs, an L3 checklist (including UI scale and a re-check of KI-1), and a test build | — |

M1–M4 cover all three starting points without touching TRP3's internals. M5 is isolated, so if the adapter has problems it can be switched off without affecting anything else.

## Technical limitations (what can and cannot be done in WoW)

| Area | Limitation | How the design handles it |
|---|---|---|
| Understanding free text | Lua 5.1 has no language model. Patterns work byte by byte, `%a` doesn't match accented letters, and nothing can resolve who "he" refers to, irony, or unreliable narrators. | No automatic extraction from free text. Sentences are *offered* to the player. Optional hints (kinship words, "born in…") are labelled **possible**, English only, and can be turned off. |
| Sentence splitting | Approximate: abbreviations ("St. Ilsa"), ellipses and dialogue will sometimes split wrongly. CJK punctuation (for example 。) needs explicit multi-byte handling. | The player can edit a pre-filled statement before approving. The verbatim source is never changed. Tests cover known awkward cases. |
| Selecting text | The game offers no dependable way to read which part of an edit box the player selected | The design uses click-a-sentence instead of selection |
| TRP3 text tags | Biographies contain `{h1}`, `{p}`, `{col:…}`, `{img:…}`, `{icon:…}`, `{link*…*…}` and similar tags | Our own simple tag stripper for display only (not TRP3's internal code). The verbatim source keeps the tags. Unknown `{…}` tags are hidden in the display; a literal brace in prose may occasionally be hidden too. |
| Pasting large text | The game's edit boxes can lag on very large pastes | A 16 KB cap per source, with a clear message when exceeded. To be confirmed at L3. |
| Saved data size | Sources add up to ~48 KB per character | Caps, plus a status line showing the stored size |
| Language | Prompts, hints and preset trait names are English only | Documented. Translations are later work. |
| Draft edits in TRP3 | If TRP3's editor is open with unsaved changes, Dawnward reads the last *saved* version | The import message says so: "Save in Total RP 3 first." |

## Unresolved compatibility risks

| # | Risk | Severity | Mitigation / status |
|---|---|---|---|
| R1 | `GetInfo("about")` is marked for deprecation and could disappear or change shape in later TRP3 versions | Medium | 3.4.1 only, inside the adapter. Shape checks before use. Fallback: paste. **3.5.3 is unaudited.** |
| R2 | Preset trait numbering is just the order of an internal table and could change | Low–medium | Name list gated to 3.4.1. Unknown versions skip presets. |
| R3 | `GetCharacteristics()` returns TRP3's live table | Medium if mishandled | Deep copy at once. Tests prove no references are kept and nothing is changed. |
| R4 | TRP3's default profile gets a new ID every login, and profiles can be shared across characters | Low | Binding refuses the default profile. Each binding is per character, and a shared profile is pointed out. |
| R5 | TRP3 data may not be ready if read too early in a session | Low | Read only when the player clicks; the reader is wrapped and fails safely |
| R6 | Other RP addons (MRP, XRP) aren't supported directly | Accepted | The paste path covers them |
| R7 | WoW Forever and TRP3 3.5.3 are untested | Unknown | The adapter is disabled there; paste and questions work |
| R8 | **KI-1** (a one-time return to character select) is unresolved | Unknown | Not linked to Dawnward. Re-checked during v0.3's L3 run. |
| R9 | New UI calls (sentence list rows, review panel) are unverified on Classic Era | Low | Same widgets as v0.2, which must pass L3 first |
| R10 | Players may read story prompts as Dawnward "understanding" their character | Product risk | Prompts are labelled "writing prompts", built from your approved facts, and say where they came from |

## Explicitly out of scope for v0.3
- Decision engine, consequences and personality changes (v0.4 or later).
- **Any** writes to TRP3.
- AI, network access or companion apps. Text drafted elsewhere can only be pasted and reviewed.
- Automatic interpretation of free text as fact.
- New main tabs or dashboards.
